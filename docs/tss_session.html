TPM2 Encrypted Sessions

EK-salted encrypted sessions protect TPM bus communication against physical sniffing attacks.

See also: TPM2 Basics | KeyVault Implementation

1. The Problem: Bus Sniffing

Vulnerability: Without encrypted sessions, decrypted data travels in plaintext over the SPI/LPC bus. An attacker with physical access and a logic analyzer can intercept secrets.

    Bus->>TSS: [plaintext response]

    Attacker-->>Bus: CAPTURED!

    TSS->>App: passphrase

    Note over Attacker: Attacker has the
decrypted passphrase!

2. The Solution: EK-Salted Encrypted Sessions

Solution: Use TPM2 encrypted sessions with Endorsement Key (EK) salting. All bus traffic is encrypted with AES-128-CFB using a session key that attackers cannot derive. 
sequenceDiagram
    participant App as Application
    participant TSS as TSS Library
    participant Bus as SPI/LPC Bus
    participant TPM as TPM2 Chip
    participant Attacker as Attacker
(Logic Analyzer)

    Note over App,TPM: ENCRYPTED SESSION (PROTECTED)

    App->>TSS: Decrypt passphrase
    TSS->>Bus: RSA_Decrypt command
    Bus->>TPM: [AES-128-CFB encrypted]

    Attacker-->>Bus: Sniffing...
    Note over Attacker: Sees only
encrypted garbage

    TPM->>TPM: RSA decrypt inside silicon
    TPM->>Bus: Encrypted response
    Bus->>TSS: [AES-128-CFB encrypted]

    Attacker-->>Bus: Still encrypted!

    TSS->>TSS: Decrypt with session key
    TSS->>App: passphrase

    Note over Attacker: CANNOT decrypt
without session key

3. Why EK Salting is Critical

Without EK salting: The session key is derived from nonces that travel in plaintext. An attacker can observe the nonces and derive the same session key!

4. Session Establishment Flow

Implementation: Using TSS2 ESYS API to establish an EK-salted encrypted session. 
sequenceDiagram
    autonumber
    participant App as TssSession
    participant ESYS as ESYS API
    participant TPM as TPM2 Chip

    Note over App,TPM: Step 1: Initialize Context
    App->>ESYS: Esys_Initialize()
    ESYS->>TPM: Connect via /dev/tpmrm0
    TPM-->>ESYS: Context ready
    ESYS-->>App: ESYS_CONTEXT*

    Note over App,TPM: Step 2: Load Application Key
    App->>ESYS: Esys_TR_FromTPMPublic(0x81010002)
    ESYS->>TPM: ReadPublic
    TPM-->>ESYS: Key metadata
    ESYS-->>App: key_handle

    Note over App,TPM: Step 3: Create Endorsement Key
    App->>ESYS: Esys_CreatePrimary(ENDORSEMENT, EK_TEMPLATE)
    ESYS->>TPM: CreatePrimary
    TPM->>TPM: Derive EK from seed
    TPM-->>ESYS: EK handle
    ESYS-->>App: ek_handle

    Note over App,TPM: Step 4: Start Salted Session
    App->>ESYS: Esys_StartAuthSession(ek_handle, HMAC, AES-128-CFB)
    ESYS->>ESYS: Generate random salt
    ESYS->>ESYS: Encrypt salt with EK public key
    ESYS->>TPM: StartAuthSession + encrypted_salt
    TPM->>TPM: Decrypt salt with EK private key
    TPM->>TPM: Derive session key from salt + nonces
    TPM-->>ESYS: Session handle + nonce_tpm
    ESYS->>ESYS: Derive session key (same as TPM)
    ESYS-->>App: session

    Note over App,TPM: Step 5: Enable Encryption
    App->>ESYS: Esys_TRSess_SetAttributes(ENCRYPT | DECRYPT)
    ESYS-->>App: Session ready

    Note over App,TPM: All future commands use
AES-128-CFB encryption

5. Code Implementation

File: source/tss_session.cpp
Step ESYS Function Purpose
1 Esys_Initialize() Connect to TPM via TCTI
2 Esys_TR_FromTPMPublic() Load persistent key handle
3 Esys_CreatePrimary() Create EK in Endorsement hierarchy
4 Esys_StartAuthSession() Start HMAC session salted with EK
5 Esys_TRSess_SetAttributes() Enable ENCRYPT + DECRYPT flags
Use Esys_RSA_Decrypt() Decrypt with encrypted session

6. Encryption Algorithm

Sessions use AES-128-CFB (Cipher Feedback Mode) for symmetric encryption.
Parameter Value Notes
Algorithm AES Advanced Encryption Standard
Key Size 128 bits Derived from session key
Mode CFB Cipher Feedback - stream cipher mode
Session Hash SHA-256 For HMAC and key derivation
