TPM2 Basics

Basic TPM2 concepts: key provisioning, signing, decryption, and key hierarchy.

See also: KeyVault C++ Implementation | Encrypted Sessions

1. Key Provisioning (Factory Setup)

Purpose: Create and persist an RSA key inside the TPM. This is done once during device provisioning. The private key is generated inside the TPM and never leaves the silicon. 
sequenceDiagram
    autonumber
    participant Admin as Factory Admin
    participant Tools as tpm2-tools
    participant TPM as TPM2 Chip
    participant NV as TPM NV Storage
    participant Disk as Filesystem

    Note over Admin,Disk: Step 1: Create Primary Key (Storage Root)
    Admin->>Tools: tpm2_createprimary -C o -g sha256 -G rsa
    Tools->>TPM: CreatePrimary command
    TPM->>TPM: Derive primary key from internal seed
    TPM-->>Tools: Primary key handle
    Tools-->>Disk: Save primary.ctx (temporary handle)

    Note over Admin,Disk: Step 2: Create RSA Child Key
    Admin->>Tools: tpm2_create -C primary.ctx -G rsa2048
    Tools->>TPM: Create command with attributes
    TPM->>TPM: Generate RSA-2048 keypair internally
    TPM->>TPM: Encrypt private key with primary key
    TPM-->>Tools: Public + Encrypted private blob
    Tools-->>Disk: Save rsakey.pub, rsakey.priv

    Note over Admin,Disk: Step 3: Load Key into TPM
    Admin->>Tools: tpm2_load -C primary.ctx -u pub -r priv
    Tools->>TPM: Load command
    TPM->>TPM: Decrypt private blob using primary key
    TPM-->>Tools: Loaded key handle (temporary)
    Tools-->>Disk: Save rsakey.ctx

    Note over Admin,Disk: Step 4: Persist Key Permanently
    Admin->>Tools: tpm2_evictcontrol -C o -c rsakey.ctx 0x81010002
    Tools->>TPM: EvictControl command
    TPM->>NV: Store key at handle 0x81010002
    NV-->>TPM: Confirmed
    TPM-->>Tools: Persistent handle assigned
    Tools-->>Admin: Key persisted successfully

    Note over Admin,Disk: Step 5: Export Public Key
    Admin->>Tools: tpm2_readpublic -c 0x81010002 -f pem
    Tools->>TPM: ReadPublic command
    TPM-->>Tools: Public key data
    Tools-->>Disk: Save tpm_rsa_pub.pem

    Note over Disk: Cleanup: Can delete primary.ctx,
rsakey.pub, rsakey.priv, rsakey.ctx
Only need handle 0x81010002 now
Security Note: The file rsakey.priv contains the private key encrypted by the TPM's primary key. This file is useless on any other device - only THIS specific TPM can decrypt and use it.

2. RSA Signing Operation

Purpose: Sign data using the TPM-resident private key. The signing happens entirely inside the TPM chip. Your application never sees the private key. 
sequenceDiagram
    autonumber
    participant App as C++ Application
    participant OpenSSL as OpenSSL 3.x
    participant Provider as TPM2 Provider
    participant Driver as /dev/tpmrm0
    participant TPM as TPM2 Chip

    App->>OpenSSL: Sign request with handle:0x81010002
    OpenSSL->>Provider: Load key from TPM handle
    Provider->>Driver: Send TPM2_ReadPublic
    Driver->>TPM: ReadPublic command
    TPM-->>Driver: Public key metadata
    Driver-->>Provider: Key info
    Provider-->>OpenSSL: EVP_PKEY (references TPM key)

    App->>OpenSSL: EVP_DigestSign(data)
    OpenSSL->>OpenSSL: Hash data with SHA-256
    OpenSSL->>Provider: Sign hash
    Provider->>Driver: Send TPM2_Sign command
    Driver->>TPM: Sign command + hash

    Note over TPM: Private key used ONLY here
Never leaves silicon

    TPM->>TPM: RSA sign with internal private key
    TPM-->>Driver: Signature bytes
    Driver-->>Provider: Signature
    Provider-->>OpenSSL: Signature
    OpenSSL-->>App: Return signature

    Note over App: App has signature but
NEVER had private key

3. RSA Decryption Operation

Purpose: Decrypt data that was encrypted with the public key. Decryption happens inside the TPM. The plaintext result is returned to your application, but the private key never leaves the chip. 
sequenceDiagram
    autonumber
    participant Sender as External Sender
    participant App as C++ Application
    participant OpenSSL as OpenSSL 3.x
    participant Provider as TPM2 Provider
    participant TPM as TPM2 Chip

    Note over Sender,App: Sender encrypts with public key (can be done anywhere)
    Sender->>Sender: Load tpm_rsa_pub.pem
    Sender->>Sender: RSA encrypt(secret, public_key)
    Sender->>App: Send encrypted blob

    Note over App,TPM: App decrypts using TPM
    App->>OpenSSL: Decrypt request with handle:0x81010002
    OpenSSL->>Provider: RSA_decrypt operation
    Provider->>TPM: TPM2_RSA_Decrypt command + ciphertext

    Note over TPM: Private key used ONLY here
Never leaves silicon

    TPM->>TPM: RSA decrypt with internal private key
    TPM-->>Provider: Plaintext
    Provider-->>OpenSSL: Plaintext
    OpenSSL-->>App: Return decrypted data

    Note over App: App has plaintext but
NEVER had private key

4. Attack Scenario: Why TPM Protects You

Scenario: An attacker clones your device's storage (SD card, SSD, etc.) and tries to use the key on different hardware. 
sequenceDiagram
    autonumber
    participant Attacker as Attacker
    participant Clone as Cloned Disk
    participant BadTPM as Different TPM
    participant Files as Stolen Files

    Note over Attacker,Files: Attacker steals/clones device storage
    Attacker->>Clone: Copy entire disk
    Clone-->>Files: rsakey.priv, primary.ctx, etc.

    Note over Attacker,BadTPM: Attempt 1: Use encrypted private key file
    Attacker->>Files: Try to load rsakey.priv
    Files-->>Attacker: Encrypted blob (useless without TPM)
    Note over Attacker: FAILED: Cannot decrypt without original TPM

    Note over Attacker,BadTPM: Attempt 2: Try on different TPM
    Attacker->>BadTPM: tpm2_load with stolen files
    BadTPM->>BadTPM: Try to decrypt rsakey.priv
    BadTPM-->>Attacker: ERROR: Decryption failed
    Note over BadTPM: Different TPM = Different primary key
= Cannot decrypt the private blob

    Note over Attacker,BadTPM: Attempt 3: Access persistent handle
    Attacker->>BadTPM: Try handle 0x81010002
    BadTPM-->>Attacker: ERROR: Handle not found
    Note over BadTPM: Key was persisted in ORIGINAL TPM
Does not exist here

    Note over Attacker: ALL ATTACKS FAILED
Key is bound to original hardware
Key Insight: The TPM's internal seed is unique to each chip and cannot be extracted. All keys derived from it are hardware-bound. Cloning the disk is useless without the physical TPM chip.

6. Runtime Application Flow

Purpose: How your C++ application uses the TPM key at runtime through OpenSSL. 
sequenceDiagram
    autonumber
    participant App as Your C++ App
    participant Poco as Poco Framework
    participant SSL as OpenSSL 3.x
    participant TPM2 as TPM2 Provider
    participant HW as TPM Hardware

    Note over App,HW: Application Startup
    App->>SSL: OSSL_PROVIDER_load("tpm2")
    SSL->>TPM2: Initialize provider
    TPM2->>HW: Open /dev/tpmrm0
    HW-->>TPM2: Connection established
    TPM2-->>SSL: Provider ready
    SSL-->>App: Providers loaded

    Note over App,HW: Load TPM Key Reference
    App->>SSL: OSSL_STORE_open("handle:0x81010002")
    SSL->>TPM2: Load key from handle
    TPM2->>HW: TPM2_ReadPublic
    HW-->>TPM2: Key metadata
    TPM2-->>SSL: EVP_PKEY (TPM-backed)
    SSL-->>App: Key handle ready

    Note over App,HW: Use Key for Signing (example)
    App->>Poco: Sign incoming request
    Poco->>SSL: EVP_DigestSignInit/Update/Final
    SSL->>TPM2: Perform signature
    TPM2->>HW: TPM2_Sign
    HW->>HW: Sign inside silicon
    HW-->>TPM2: Signature
    TPM2-->>SSL: Signature bytes
    SSL-->>Poco: Signed data
    Poco-->>App: Return signature

    Note over App: Key never in app memory!
Only signature returned
