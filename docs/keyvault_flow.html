Bus Protection: All TPM communication uses EK-salted encrypted sessions. See Encrypted Sessions for details.
Security: Process hardening is applied before any secrets are loaded. This ensures the protections are in place from the start.

2. Protecting a User Passphrase

Phase: User uploads encrypted PEM file and provides passphrase.
Method: KeyVault::protect(key_id, passphrase) 
sequenceDiagram
    autonumber
    participant User
    participant App as Application
    participant KV as KeyVault
    participant SSL as OpenSSL
(default provider)
    participant FS as Filesystem

    User->>App: Upload PEM + passphrase
    App->>KV: protect("user_key_A", passphrase)

    Note over KV: Create isolated OpenSSL context
(no TPM provider)

    KV->>KV: OSSL_LIB_CTX_new()
    KV->>SSL: OSSL_PROVIDER_load(ctx, "default")

    KV->>FS: fopen(pubkey_path)
    FS-->>KV: FILE*
    KV->>SSL: PEM_read_PUBKEY()
    SSL-->>KV: EVP_PKEY* (public key)

    Note over KV,SSL: RSA encrypt passphrase
with TPM public key

    KV->>SSL: EVP_PKEY_encrypt_init()
    KV->>SSL: EVP_PKEY_CTX_set_rsa_padding(PKCS1)
    KV->>SSL: EVP_PKEY_encrypt(passphrase)
    SSL-->>KV: encrypted_blob (256 bytes)

    KV->>KV: Cleanup contexts
    KV-->>App: ProtectedPassphrase{key_id, encrypted_blob}

    Note over App: Store in database

    App->>App: protected_pass.serialize()
    App->>FS: Store blob to DB

    Note over User,FS: Passphrase now protected
Original passphrase can be wiped

Phase: Runtime - sign data using TPM-protected passphrase.
Method: KeyVault::sign_with_protected_key() 
sequenceDiagram
    autonumber
    participant App as Application
    participant KV as KeyVault
    participant TSS as TssSession
    participant TPM as TPM2 Chip
    participant SB as SecureBuffer
    participant SSL as OpenSSL

    App->>KV: sign_with_protected_key(protected_pass, pem_path, data)

    rect rgb(255, 240, 240)
        Note over KV,TPM: VULNERABLE WINDOW BEGINS

        KV->>KV: load_protected_key()

        Note over KV,TPM: Step 1: TPM decrypts passphrase (encrypted bus)

        KV->>TSS: decrypt(encrypted_blob)
        TSS->>TPM: Esys_RSA_Decrypt (AES-128-CFB encrypted)
        TPM->>TPM: RSA decrypt inside silicon
        TPM-->>TSS: plaintext (AES-128-CFB encrypted)
        TSS-->>KV: SecureBuffer(passphrase)

        Note over SB: Memory mlocked
Cannot be swapped

        Note over KV,SSL: Step 2: Load encrypted PEM

        KV->>SSL: PEM_read_PrivateKey(pem, passphrase)
        SSL->>SSL: AES-256-CBC decrypt PEM
        SSL-->>KV: EVP_PKEY* (user private key)

        Note over SB: Step 3: Wipe passphrase immediately

        KV->>SB: ~SecureBuffer()
        SB->>SB: volatile wipe loop
        SB->>SB: munlock()

        Note over KV,SSL: Step 4: Sign operation

        KV->>SSL: EVP_DigestSignInit(pkey)
        KV->>SSL: EVP_DigestSignUpdate(data)
        KV->>SSL: EVP_DigestSignFinal()
        SSL-->>KV: signature

        Note over KV,SSL: Step 5: Wipe key

        KV->>SSL: EVP_PKEY_free(pkey)

        Note over KV,TPM: VULNERABLE WINDOW ENDS
    end

    KV-->>App: signature

    Note over App: Only signature returned
No secrets in scope
Vulnerable Window: Between passphrase decryption and key wipe (~1-10ms). Mitigated by process hardening but not eliminated for user-provided keys.

Realistic Timing Breakdown (Intel Elkhart Lake)

Phase Duration Passphrase User Private Key Status
TPM RSA-2048 decrypt 50-200ms Encrypted → SecureBuffer Encrypted (in PEM file) SAFE
PEM AES-256 decrypt ~50μs In SecureBuffer Being decrypted PARTIAL
Both secrets in RAM ~1-2ms In SecureBuffer In EVP_PKEY VULNERABLE
Sign operation ~1-2ms WIPED In EVP_PKEY PARTIAL
Cleanup ~10μs WIPED FREED SAFE

Attack Probability Analysis

Scenario: Attacker with root + CAP_SYS_PTRACE attempting to read process memory during key operation.
Attack Vector Window Probability per Attempt Notes
Blind memory scan (random timing) ~3ms / 200ms total ~1.5% Must hit the ~3ms vulnerable window within ~200ms operation
Continuous polling (/proc/pid/mem) ~3ms window ~10-30% Polling overhead ~100μs, may catch window but data fragmented
ptrace + breakpoint N/A BLOCKED PR_SET_DUMPABLE=0 prevents attach
Core dump trigger N/A BLOCKED RLIMIT_CORE=0, PR_SET_DUMPABLE=0
Cold boot / DMA attack ~3ms <0.1% Physical access + precise timing nearly impossible
Key Insight: Even with root access, the ~3ms vulnerable window within a ~200ms operation gives only 1.5% exposure ratio. Combined with mlock (no swap), process hardening, and the need for precise timing, practical extraction requires multiple attempts and leaves forensic traces.

Exposure Ratio Calculation

Total operation time:     ~155ms (TPM: 150ms + RAM ops: 5ms)
Full exposure window:     ~2ms   (both secrets in RAM)
Partial exposure window:  ~3ms   (one secret in RAM)

Full exposure ratio:      2ms / 155ms = 1.3%
Any exposure ratio:       5ms / 155ms = 3.2%

For 1000 operations/day:
  - Total exposed time: ~5 seconds/day
  - Attacker must be:
    1. Root with CAP_SYS_PTRACE
    2. Actively scanning during that exact 5 seconds
    3. Able to reassemble fragmented memory reads

7. PCR Policy Session Flow

Phase: When PCR policy is configured, the TPM requires a policy session and PCR verification.
See: PCR_POLICY.md for detailed documentation. 
sequenceDiagram
    autonumber
    participant App as Application
    participant KV as KeyVault
    participant TSS as TssSession
    participant TPM as TPM2 Chip

    Note over App,TPM: Session type depends on PCR policy

    App->>KV: Initialize KeyVault
    KV->>KV: Read keys/pcr_policy file

    alt No PCR Policy
        KV->>TSS: Create HMAC session
        TSS->>TPM: StartAuthSession(TPM2_SE_HMAC)
    else PCR Policy Configured (e.g., PCR 16)
        KV->>TSS: Create POLICY session
        TSS->>TPM: StartAuthSession(TPM2_SE_POLICY)
    end
    TPM-->>TSS: Session handle

    Note over App,TPM: During decrypt operation

    App->>KV: decrypt(ciphertext)

    alt PCR Policy Required
        KV->>TSS: Satisfy PCR policy
        TSS->>TPM: Esys_PolicyPCR(session, PCR_16)
        TPM->>TPM: Check: PCR 16 matches expected value?

        alt PCR Matches
            TPM-->>TSS: Policy satisfied
        else PCR Mismatch
            TPM-->>TSS: TPM2_RC_POLICY_FAIL
            TSS-->>KV: Error: policy check failed
        end
    end

    KV->>TSS: RSA_Decrypt with session
    TSS->>TPM: Esys_RSA_Decrypt (encrypted)
    TPM-->>TSS: Plaintext (encrypted on bus)
    TSS-->>KV: SecureBuffer(plaintext)
    KV-->>App: Decrypted data
PCR Value Requirement: Before running the application, the PCR must be extended with the correct value (e.g., ./scripts/pcr.sh boot). Otherwise the operation will fail.
